# Clinging: Reoriented hardening analysis

Status: **TEMPORARY — DELETE ON SUCCESS**.

## 1. Current-state classification

### Keep and harden in Clinging

- `ClingingReoriented`: voluntary selection, player ownership/reconciliation and retirement policy.
- `AirChanges`: airborne charge semantics.
- `MobGravity` / `MountedGravity`: generic effect/rider gravity policy for eligible living roots; ownership and recovery need rework.
- `GravityInput`, `LookDirection`, `GravityBreadcrumbs`, brewing/beacon behavior: retain unless a regression is found.
- Client input/reply/state protocol for Clinging turn intent: retain.

### Rework now

- `ClingingReoriented.retire`: replace remote `lastSafeDown` and full-column search with bounded local recovery + pending retry.
- `PlayerData`: remove remote-safe-position semantics; keep only state needed by the bounded lifecycle.
- `MobGravity.State`: replace `effectSeen` as an ownership proxy with explicit ownership/borrow semantics and prior-frame restoration where required.
- `MobGravity.restore`: make candidate placement atomic for the complete passenger hierarchy.
- `CameraDurationMixin`: stop globally replacing Gravity Changer timing; gate by a Clinging-owned visual transition lifecycle.
- `FirstPersonOffsetMixin`: use the same visual ownership boundary instead of acting as a global Gravity Changer compatibility patch.
- `MovingSurface`/`MoveReference`: add minimal causal anti-replay hardening only.

### Remove the Tiny-Mount-specific branch from Clinging

Current `MountedGravity` already works on the generic contract `rootVehicle instanceof LivingEntity`, rejects player roots and asks only whether the root supports Gravity Changer gravity. It contains no Tiny Mount concept.

The three Scale-specific mixins:

- `ScaleFlightGravityMixin`
- `ScaleWolfGravityMixin`
- `ScaleChickenGravityMixin`

exist only because particular Scale-generated mechanics currently assume world-Y/world coordinates. They repair Scale's bee flight, wolf pounce/landing and chicken glide after Clinging has already put the mount in a non-DOWN frame. That is not a separate mounted-gravity contract; it is Scale correcting impulses produced by its own mount mechanics.

Therefore the target boundary is:

```text
Clinging generic mount path
Player passenger → LivingEntity root → Gravity Changer frame/turn

Scale Tiny Mount internals
Generate flight/glide/pounce contribution in the root's effective gravity frame
```

Clinging must not detect a Tiny Mount, negotiate a Tiny capability or choose an alternate transfer path. A Tiny Mount is simply a mount externally.

### Delete later at Scale G7

Subject to the final Scale public API and successful consumer tests, Clinging should lose ownership of responsibilities represented by `MovingSurface`, `EntityCollisionMixin`, `OutgoingMoveMixin`, Scale-specific movement baselines/reconciliation, `ScalePhysicsMixin`, and most of the current Scale/Anatomy bridges. Exact symbol deletion is decided against the final API, not precommitted by name.

This G7 migration concerns anatomical contact/carry/reconciliation. It must not be confused with mounted gravity, which remains a generic Clinging/Gravity Changer relation over ordinary passenger roots.

## 2. Design decisions accepted

1. Player forced retirement is local-only (≤4 blocks), otherwise pending/retry.
2. Gravity ownership is explicit and external gravity is preserved.
3. Camera timing and First Person correction are local to Clinging-owned visual transitions.
4. All eligible living mounts use one Clinging mounted-gravity contract. Tiny Mounts are not a special category.
5. Scale owns correctness of forces/impulses generated by Scale-specific mount mechanics under the root's effective gravity frame.
6. Scale Brews G7 is the future owner of shared entity-surface physics/reconciliation, not mounted-gravity policy.

## 3. Coordination with Scale Brews

Scale `chatgpt-editing` is currently executing the mandatory S00 foundation audit. Its target architecture already contains a single-owner gravity adapter (FR-073/074) and currently contains `collision.internal.GravityFrames`. Tiny Mount mechanics also need an effective gravity frame, but that need does not justify a Tiny-Mount-specific public channel.

The desired long-term topology is:

```text
Gravity Changer / effective entity gravity
                ↓
     canonical Scale frame reader/service
          ↙                    ↘
future collision consumer   Scale mount mechanics

Clinging generic mounted gravity
  └── sets/owns the mount root gravity through Gravity Changer
      without knowing whether the mount is Tiny, vanilla or another compatible living mount
```

Scale must remain loadable without Gravity Changer. Its integration therefore must be optional/gated, not a required dependency. The exact shared service must later be reconciled with `chatgpt-editing`; this branch must not modify the other agent's active S00 work.

## 4. Release consequence

The next Clinging prerelease does not need to support or certify unfinished Scale Brews. There is no beta.5 compatibility-overlap requirement, no native Tiny capability marker and no old/new Scale shim negotiation.

The release contract is simpler:

- Clinging prerelease validates its generic mounted-gravity behavior without Scale;
- Scale's own branch validates that Tiny Mount-generated mechanics honor whatever gravity the mount root already has;
- once Scale as a whole reaches the intended integration milestone, cross-repo validation can prove that an actual Tiny Mount travels through the same generic `MountedGravity` path, with no Clinging special case.

## 5. Iterative convergence record

- **Pass 1:** split fixes into player recovery, mob ownership, passenger atomicity, visual ownership, moving-surface networking and Scale migration.
- **Pass 2 change:** rejected building a full new Clinging movement-reference protocol because Scale G4/G7 already owns the permanent solution; reduced this to bounded anti-replay hardening.
- **Pass 3 change:** separated Tiny Mount gravity from entity collisions; Scale-specific generated impulses belong to Scale `mount`, not `collision`.
- **Pass 4 change:** originally added a native-capability/shim overlap for Scale beta.5.
- **Pass 5 change:** identified the need for one transversal Scale gravity-frame authority so future collision and Scale mount mechanics do not disagree.
- **Pass 6 change after owner review:** rejected the compatibility-overlap design entirely. Scale will not be used until the relevant Scale work is complete, and Tiny Mounts must conform to the same generic mount contract as every other eligible living mount. Removed capability markers, version gates and Tiny-specific Clinging channels from the target design.
- **Pass 7:** reviewed requirements, current `MountedGravity`/`MobGravity`, the three Scale-specific mixins and the Scale workstream against the new invariant. No architectural reason was found to distinguish Tiny Mounts at the Clinging contract boundary.
