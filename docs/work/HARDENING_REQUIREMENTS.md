# Clinging: Reoriented hardening requirements

Status: **TEMPORARY execution requirements — DELETE ON SUCCESS**.

Purpose: define the behavior that must be true before the next Clinging: Reoriented prerelease. These requirements cover correctness hardening, ownership boundaries and the generic mounted-gravity contract. Permanent product docs are updated only after implementation and validation succeed.

## 1. Scope and invariants

- **CR-001 Bounded player retirement.** When the last Clinging/Reorientation-owned source disappears, returning to DOWN must first be attempted in place. If blocked, recovery may relocate only within a maximum Euclidean displacement of 4 blocks from the current retirement origin. No remote `lastSafeDown` teleport and no unbounded/full-column vertical scan are permitted.
- **CR-002 Pending retirement.** If no valid DOWN placement exists within the bounded recovery region, the current gravity may remain temporarily while `retirementPending` is true. New voluntary turns are blocked, ordinary movement remains possible, and retirement is retried periodically until a safe local DOWN placement exists or a lifecycle discontinuity resolves the state.
- **CR-003 Recovery safety.** Recovery never edits blocks, never loads/generates chunks solely to search, respects world border/height/collision, and fails closed when geometry is unavailable.
- **CR-004 Explicit gravity ownership.** Clinging must distinguish gravity it owns from gravity owned by another source. It may restore/retire only gravity it acquired or borrowed. Merely observing Clinging/Reorientation on an entity does not grant ownership of an existing external gravity state.
- **CR-005 Mob ownership semantics.** Passive mobs must distinguish at least the semantic states NONE, OWNED_EFFECT, BORROWED_RIDER and EXTERNAL (implementation representation may differ). External writes while Clinging owns gravity revoke or transfer ownership according to an explicit deterministic rule; they must never later be silently reset to DOWN by stale Clinging state.
- **CR-006 Borrowed mount restoration.** When Reorientation temporarily transfers a rider frame to a mount, the mount's prior externally owned frame must be preserved/restored when the loan ends unless the mount independently acquires Clinging ownership meanwhile.
- **CR-007 Atomic root/passenger recovery.** Any voluntary or forced root gravity change/relocation involving passengers must preflight the complete passenger hierarchy before mutating position, gravity, momentum or passenger placement. A failed candidate produces zero observable mutation.
- **CR-008 Clinging-local camera timing.** `cameraRotationSeconds` applies only to visual gravity transitions initiated/owned by Clinging or Reorientation, including their return-to-DOWN animation. Unrelated Gravity Changer transitions retain Gravity Changer timing.
- **CR-009 Clinging-local First Person compatibility.** First Person offset correction applies only while presenting a Clinging-owned visual transition/frame. Installing Clinging must not become a general First Person ↔ Gravity Changer patch for unrelated gravity sources.
- **CR-010 World momentum.** Gravity-frame changes never retroactively rotate already existing world-space momentum. New impulses generated by a mechanic may be expressed in the current gravity frame when that mechanic owns that impulse.
- **CR-011 Temporary MovingSurface hardening.** Until Scale Brews G7 migration, the legacy moving-surface protocol must reject replay/stale causal references strongly enough that a client cannot obtain a second material correction from an old but once-valid support sample. Accepted references are bounded in age, monotonically ordered, one-shot/consumed and invalidated by support/revision/teleport/dimension discontinuities.
- **CR-012 No second permanent transport protocol.** CR-011 is intentionally transitional. Clinging must not grow its own final epoch/receipt/prediction architecture that duplicates the Scale Brews G4/G7 destination.
- **CR-013 Preserve core gameplay.** Fresh airborne jump input, one successful Clinging turn per airborne stretch, unlimited Reorientation turns, Elytra priority, anchors, sounds, brewing, beacon behavior, pet breadcrumbs, persistence and server authority must remain behaviorally compatible unless another requirement explicitly changes them.
- **CR-014 Scale independence for this prerelease.** The next Clinging prerelease must not require, target or claim compatibility with an unfinished Scale Brews collision stack. Core Clinging functionality and release validation remain valid with Scale absent.
- **CR-015 Generic mounted-gravity contract.** Clinging must treat every eligible non-player `LivingEntity` root vehicle through the same `MountedGravity`/`MobGravity` contract. A Tiny Mount is not a separate mount category from Clinging's perspective. No Tiny-Mount-specific capability marker, version gate, compatibility shim or alternate gravity-transfer channel may be introduced.
- **CR-016 Remove Tiny-Mount-specific Clinging patches.** Scale-specific patches whose only purpose is to reinterpret Tiny Mount flight/glide/pounce under non-DOWN gravity must not remain part of Clinging's long-term implementation. Scale owns correctness of impulses generated by its own mount mechanics; Clinging owns only the generic mounted gravity state/policy.
- **CR-017 Future G7 ownership.** When Scale Brews' public collision API and prerequisites are stable, Clinging must cease owning anatomical entity collision, moving-surface carry, transport baselines, movement references and reconciliation for Scale-managed contacts. This future migration is separate from generic mounted gravity.
- **CR-018 Documentation truth.** At successful completion, README/GUIDE/ARCHITECTURE/CONFIGURATION/COMPATIBILITY/VALIDATION/CHANGELOG must be reviewed against the final code while preserving each document's scope. Temporary work files are deleted before final merge.
- **CR-019 Prerelease delivery.** The next Clinging prerelease must follow the established public prerelease style: semantic prerelease increment, prerelease flag, exact validated target commit, regular JAR asset, release notes summarizing behavior and validation without overstating manual QA, and post-publication target/asset verification.

## 2. Non-functional requirements

- **CNFR-001 Server authority.** Client input may express intent but cannot author gravity ownership, geometry, contact, support history or material transport.
- **CNFR-002 Fail closed.** Missing/unknown optional integration state disables the affected optional behavior rather than inventing geometry or accepting stale authority.
- **CNFR-003 Determinism.** Candidate recovery and ownership transitions must not depend on hash/iteration order.
- **CNFR-004 Bounded work.** Recovery search, network history and adversarial inputs are bounded in space/time/memory.
- **CNFR-005 Minimal side effects.** Fixes must be scoped to Clinging-owned behavior; no global mutation of unrelated Gravity Changer or optional-mod behavior.
- **CNFR-006 Backward compatibility.** Existing alpha.6 worlds must load without manual migration. Removed legacy NBT keys may be ignored safely.
- **CNFR-007 One mount contract.** Mount policy must depend on generic vehicle/entity capabilities, not concrete Scale classes, Tiny Mount definitions or Scale version/capability probes.
- **CNFR-008 Reviewability.** Work is split into small dependency-coherent commits/sprints, no force-push/history rewrite, no release/tag before final validation.

## 3. Acceptance outline

The final implementation must include adversarial regression coverage for bounded recovery, external gravity ownership, nested passenger atomicity, visual ownership leakage, stale/replayed moving-surface references and the generic mounted-gravity path. At least one ordinary non-Scale mount fixture must prove the mounted contract without any Tiny-Mount-specific branch. Scale-specific generated-impulse correctness is tested in Scale Brews, not made a release dependency of this Clinging prerelease.
